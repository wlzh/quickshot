- UI 夹具覆盖识别窗口首击工具栏、双击复制/进入主窗口、普通窗口直接进入编辑器和设置开关状态；`npm run verify` 已通过。

有几处需要明确区分：

- 选区阶段和编辑器阶段都支持裁切；编辑器裁剪与标注共用撤销/重做历史。

## 首批的实现边界与验收点

### 1. 已有图片进入同一编辑流程

增加“打开图片”入口，并支持拖入和粘贴。主进程把图片解码为现有预览会话使用的数据；取消导入时保留当前编辑内容。已有美化参数、标注、导出与 OCR 应继续可用。需要分别验证 macOS/Windows 的文件和剪贴板入口，普通图片的逻辑尺寸不能直接套用 Retina 截图密度。

### 2. 裁剪与查看细节

增加裁剪框与确认/取消，保留原图以便撤销；同时提供适应窗口、100%、放大/缩小和空格平移。裁剪需要与标注共用文档历史，处理裁剪后坐标、画面比例和 OCR 的有效区域。验收包含已有文字/箭头跨裁剪边界、连续撤销/重做、1x/2x 图片及大图查看。

### 3. 可编辑的局部放大与聚光灯

局部放大保留来源区域与展示区域，支持倍率、边框和移动；聚光灯支持矩形或圆形区域、遮罩强度。两者进入现有的选择、缩放、撤销与导出体系。放大取样应遵循打码结果，避免同一截图中的已遮盖内容在放大框里重新出现；预览、复制、保存需保持一致。

### 4. 多套样式预设

在现有 `StyleSettings` 和默认样式上增加名称、保存、重命名、删除和应用。先复用现有渐变、边距、阴影、框架、比例与水印参数，不新增外部素材。应用预设影响美化参数，保留已画标注；升级时承接用户现有默认样式。

## 后续功能的结构依赖

编辑器历史当前持有 `EditorDoc`，包含标注、拼接图块和裁剪区域；样式另行持久化。可重新打开的编辑工程仍需带版本的文档格式及图片资源管理，不能直接把当前内存历史当成工程文件。

导出格式应贯通渲染结果、主进程验证、扩展名和保存入口。透明图输出 JPG 时要有明确的背景填充；复制和贴图可以继续使用 PNG。缩放预览与改变导出像素尺寸需要分别控制。

普通 OCR 返回文字与行数；辅助智能打码使用 [macOS helper](../native/quickshot-ocr/main.swift) 的 `--words` 模式及 [结果解析器](../electron/ocrResult.ts) 提供的词框，Windows 也有对应词框路径。规则匹配只提供候选，不应宣称识别了所有敏感信息；发送前仍需人工确认。

macOS 滚动截图已有可运行实现和拼接测试；固定页头、动画、懒加载和滚动容器仍可能影响结果。Windows 滚动截图与更复杂的接缝编辑属于后续工作。

历史记录保持本地，并让用户选择是否启用及保留数量/时间。工程文件需要版本、图片与标注一起保存；单纯保存 PNG 无法恢复编辑对象。
